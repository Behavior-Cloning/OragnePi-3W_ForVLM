# 对话保存、删除和上下文

当前实现：原生网页 + 浏览器 IndexedDB + 板端 llama.cpp；未建设账户和服务器历史数据库。

## 对话生命周期

1. 点击“新建对话”创建空会话，发出第一条消息后写入 IndexedDB 数据库 `orange-vlm`。
2. 每轮发送时保存用户文字/压缩图片，生成结束后保存模型回答和状态；没有固定过期时间。
   流式回答不会逐 token 写入存储：生成途中关闭/刷新页面，尚未保存的回答可能丢失，
   再打开会把原“生成中”记录显示为“已停止”，不会自动续写；最好等回答完成后关闭。
3. 刷新、关闭页面、重启开发板后，仍可在原浏览器和原网址恢复；不会同步到其他浏览器或设备。
4. 浏览器按来源（协议、IP/域名、端口）隔离存储。更换板卡 IP、端口或浏览器后可能看不到原记录，
   不代表原来源中的数据已经删除。清理网站数据、隐私模式结束或浏览器存储回收可能使历史丢失。
5. 左侧每条会话有“删除”按钮；顶部“删除对话”删除当前会话。确认框显示目标标题。
   确认后删除这段会话的浏览器记录及图片；取消不修改数据。删除非当前会话保留当前对话。
   生成期间暂时禁止删除/切换，避免把正在写入的会话删掉后又保存回来。

“新建对话”只清空新请求的会话上下文，旧记录仍在列表。删除对话不会更改模型权重，
聊天内容也不会因此被训练进模型。板端可能仍有用于加速的临时 KV/prompt 缓存，
浏览器删除不是对进程内存的安全擦除；应用新请求只发送当前选中会话，不会拼入其他会话历史。
多标签页之间尚未实现实时同步，删除时建议避免另一个旧标签页继续写回同一会话。

## 可调上下文与超窗处理（更新）

输入框上方可选择已下载模型，以及 1024、2048、4096、8192 token 窗口，点击“应用并加载”后生效。
设置是板端共享配置，会影响其他访客；生成和加载期间禁止切换。模型文件校验、服务重启和健康验证完成前
显示等待状态。加载失败回滚原配置；设置保存在板端，重启后仍使用最后成功配置。

当前已取消约 15 轮的网页硬限制，改用实际后端窗口判定：输入超窗时，逐次移出最早的完整问答轮次，
直到能容纳当前输入。系统提示和最新用户消息始终保留。如果最新问题/图片单独仍超窗，则明确报错，
不静默截断新问题或图片。暂未实现自动摘要。

移出历史是“后续不再提交给模型”，不是删除浏览器记录。界面会标记已移出的消息并显示提示，
保存裁剪起点，刷新后仍沿用；增大窗口不会自动把已移出的旧消息重新放回模型。
图片随所属旧轮次移出后，也不再被模型看到，需要用户重新上传才能继续针对它提问。
停止/失败导致的空助手消息不计入实际提交消息数，但原始历史仍保留。

保留 `--no-context-shift`；裁剪由网页网关按消息边界显式执行，不让推理引擎随意拆断图片 token。
窗口同时容纳输入和输出，但网关只在输入被后端判为超长时重试裁剪；
输入刚好接近窗口时，剩余生成空间可能不足 256 token，届时显示长度截断提示。

真实 1024 窗口测试：过长的旧用户消息+旧助手消息被移出（响应头 `X-Context-Dropped: 2`），
最新问题正常返回 HTTP 200；单条 2552-token 输入则返回 HTTP 400，不删改最新问题。
多浏览器使用时，如果发送前模型或窗口被别人改变，网关返回冲突提示，而不是悄悄使用另一个模型。

## token 的含义

4096 是默认窗口之一，不是浏览器能保存的字符数，也不是 4096 个汉字。
系统提示词、历史用户和助手消息、图片产生的视觉 token、当前问题以及新回答都占用窗口。
不同模型对同一张图片的分块和 token 数可能不同；字符数不能准确预测剩余容量。
本次同图测试中，含系统提示和问题的输入总计为 SmolVLM 约 260 token、InternVL3-1B 约 1342 token；
这不是每张图片固定的 token 价格。具体数据见 [多模型板端对比](多模型板端对比.md)。

每次请求会重新提交尚未移出上下文的当前会话文字和图片；推理引擎可复用前缀缓存加速。
这就是同图追问往往比第一次看图快的原因，不是模型在后台永久记住了这张图。

另外存在两个独立限制：

- 网关单次最多接受 1024 条消息，且请求体限 16MiB；这仍是传输/资源限制，不是无限历史容量。
- 网页请求单次回复最多 256 个 token，并不保证能把长答案说完。

输入超过上下文时，后端先拒绝，网关按上述策略移出旧轮次并重试，界面显示提示。
如果生成时触及输出长度或可用上下文边界，回答也可能提前结束；后端返回 `finish_reason=length` 时，
网页在回答下方明确显示“已达到输出长度或上下文限制”，刷新后仍保留提示。
已有历史不会因此删除，可复制需要的内容，在新会话中补充简短背景及需要的图片。

旧版“只拒绝不裁剪”行为下的板端 InternVL3-1B 实测：API 长输入被分词为 12063 token，返回 HTTP 400，
`exceed_context_size_error`，明确报告 `n_ctx=4096`，随后健康检查仍为 ready。
该测试通过 API 绕过网页单条输入字符限制，仅用于验证后端窗口边界；
网页的错误显示另由集成测试验证。原始响应见
[网页验收记录](benchmarks/2026-10-09-models/web-acceptance.json)。

浏览器没有精确的 token 用量条，目前不能声称“还剩多少 token”；精确值需要实际模型 tokenizer
和图像编码策略支持。当前健康接口返回已应用的实际窗口。

网页新回答显示端到端总耗时、首个文字片段到达时间，以及后端报告的解码 token/s；
“系统负载与存储”展开后每约 3 秒显示资源采样。整机 CPU 满载为 100%，模型 CPU 单核满载为 100%，
两者分母不同。磁盘可用值使用文件系统普通用户可用空间，RAM 使用 MemAvailable；空闲文件缓存可回收。

## 容量之外的限制

输入框单条最多 4000 字符，网页将图片压缩至最长边 768 像素；API 的请求体上限为 16MiB。
这些限制和模型 4096-token 窗口不是一回事。图片数量、内容和模型 tokenizer 都会影响实际窗口用量。
服务只有一个推理槽位，多台设备同时发送会竞争/等待；不会因此共享浏览器聊天记录。
网页网关当前对并发生成/切换明确返回“正在生成或加载”，不静默排队。
点击停止会关闭上游连接并尽快释放网页请求；底层视觉计算是否立刻停止取决于引擎检查取消的时机。
