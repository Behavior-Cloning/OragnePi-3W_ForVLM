# C512 原精度 M16 / M32 / M16-repeat 独立结果审计

结论：实测数据链完整、M32 热请求 TTFT 配对中位降低约 14.10%，decode 没有实质改变。但不满足 100 ms 目标，也不满足动作决策质量验收。原图量化常量相同不代表不同 batch 形状的实际输出逐位相同。

本审计只读取 Windows/WSL 已回收文件；没有调用 SDK、访问板卡或重跑模型。独立计算未导入主分析器。机器证据分别保存在 INDEPENDENT_NUMERIC_AUDIT.json 与 INDEPENDENT_MANUAL_REVIEW.json。

## 覆盖及契约

72 条性能、144 条自然输出、24 条四步诊断、3 次正常关闭逐条核对，唯一 (variant, case) 集合完整。每版：24 性能（8 格 × 3 场景 × 1 次）、48 自然（旧调试集 24 + 预先冻结家庭场景 24）、8 诊断 × 4 步。后三者不是同一个质量指标。48 个实际 NB 文件重新读取 SHA/尺寸；板端保存的每版 29 主图 + 12 尾图 SHA 与配置相同。所有 loaded 为同一个 bf19922f… binary、24 层、capacity512、greedy/true8 开启。三次 driver_bytes 均归零，无 I16 首块切换标记。

输入静态完整模板 64/128（正文 59/123 + 模板 5）；动态正文 64/128/192/256，另有模板 8，实际新增 72/136/200/264。全部请求先 reset、仅准备 system，然后实际复用恰为 64/128；没有预先计算动态 KV。M32 同时改变 system 的 batch 分块，所以本对照包含固定 KV 的数值变化，不能称纯动态调度实验。所有动态请求确有一次真实 M8 尾图调用、尾行 8、scalar=0；最大请求末 KV=423，小于 512。

性能固定反馈 32 步且 diagnostic=false、profile=none；decode 重新计算为 31/(total−TTFT)，首 token 不重复计入 decode 分子。自然输出使用 EOS / 最长 32，不固定反馈。诊断单独记录四步、完整 151674 词表，不进入速度统计。上传 config 的 SHA 与恢复 config 不同只是一个尾换行：已逐字确认 JSON 一致；不是配置变更。

## 实际数值与自然语义

24 份真实 logits 文件均重新读入为 4×151674 FP32，实际 SHA、字节数、finite 和 argmax 对齐 metrics.tokens。原图 A-A 8/8 文件逐位相同；M32 8/8 不同，全词表 relative L2=2.932%–3.285%，maxabs 0.4648–0.5664，诊断 32/32 argmax 相同。诊断只覆盖各格首场景及四个固定反馈位置，不足以证明自然生成稳定。

M32 自然旧集 21/24、新集 22/24 输出 token 序列相同；原图重复 48/48 相同。全部 144 回复、432 个 RAG 候选已人工阅读；复用既有判断仅在输入 token SHA、回复字节、gold、实际候选 ID 全同的情形。不是盲评，也不是大样本准确率估计。所谓新冻结集在早期运行前冻结，但如今已被多轮观察，不能再声称是本轮从未见过的独立留出集。

| 变化案例 | M16 → M32 | 语义判定 |
|---|---|---|
| s64-d128-waist-bow | 鞠躬一次。 → 鞠躬一次 | 标点变化；均未明确仅腰部/轻幅度 |
| s64-d128-head-left | 头部向左转一点。 → 调整头部位置，向左转一点。 | 高层意思兼容；RAG Top3 中可用的 R001 反而被 R010 替换 |
| s128-d128-head-left | 左转 → 左转头部 | 部件指代改善，仍遗漏小角度 |
| s64-d192-sleep-stop | 保持全身静止。 → 停止底盘运动。 | 从完整静止要求退为仅底盘停止；是约束遗漏，不能夸大成明确命令手臂运动 |
| s128-d192-arm-low-wave | 摆弄桌子 → 右臂挥动一次 | 消除未授权物体操作，改善为兼容动作，但仍遗漏低幅度及停住边界 |

旧 24：M16=9 完整、9 兼容但遗漏、3 安全不响应、3 信息不足；M32=9/10/3/2。新 24：M16=5 完整、7 兼容但遗漏、6 安全不响应、2 信息不足、1 场景复述、3 显式冲突；M32=4/9/6/2/1/2。两种静态长度的“摇头”仍答“点头”；s64 长挥臂请求仍复述背景。局部改善不足以通过整体质量门。

RAG 必须相对原始高层指令和禁止项判定，不能顺着错误回复评为相关。M16 Top1 显式冲突 20/48，M32 19/48；两版均 48/48 的 Top3 至少包含一个显式冲突，不允许依次执行。兼容候选也仍需幅度/速度/边界参数绑定。所有候选均 mock_only=true、enabled_on_board=false。

## 资源、音频及稳定性边界

2110 份资源样本覆盖 1087.015 秒，约 18.1 分钟；这是一次带各阶段的 A-B-A 实验，不是新的 1 小时持续压力资格。全 8 核加权 CPU 7.392%（约 0.591 核），区间采样最大 29.078%；load1 P50=3.49、最大4.01。温度最高49.786°C。监测进程 RSS 和 PSS 峰值分别626.863/618.906 MiB；这些不含 NPU driver 存储，不能当全系统总内存。MemAvailable最低2477.570 MiB。

按版本的桶包含加载、性能、自然、诊断和关闭，且背景进程贯穿三版；不能拿三个峰值差推导独立常驻模型内存。NPU每版关闭均为0；不等于内核页面缓存或背景 swap 清零。

系统 swap 使用319→829 MiB；pswpout增加130560页，pswpin增加5页，不能称无swap。CPU6/7采样均为2002000 kHz，A55范围416000–1794000 kHz；无法从采样频率/温度单独证明没有瞬态限频或内核故障。

语音前端结束68916帧、3393帧超16 ms预算（4.923%），最大compute=1.0443 s、lag=1.0469 s；最大值在首个资源样本、首个性能请求之前已出现，不能归因于M32，也不能无证据删掉当成无关暖机。队列上限1、无后台线程异常，但并不等于严格实时通过。172次音频端点记录没有替代ASR准确率、真实麦克风、触发→动作端到端延迟验证。

本审计允许把M32作为隔离后续实验的对照，不能晋升为动作产品默认；仍需修复高层约束与RAG冲突，并单独满足性能目标。没有访问板卡补采内核日志，因此不对未记录时段作“无内核错误”结论。
