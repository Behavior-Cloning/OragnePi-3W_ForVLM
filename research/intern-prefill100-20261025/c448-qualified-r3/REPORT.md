# C448 运行时与量化来源修复验证

2026-10-26，独立候选 `c448-qualified-r3`，不是默认部署。

修复了旧 runtime 的 tail8 容量白名单：旧二进制只允许 C256/C512，C448在载入主图后return2；新版本增加C448，保留实际KV shape/dtype/quantizer契约检查。Host缓存检查5520项通过。新编译C448原量化L2/L3的M32和M8图，其他图保持同轮一致。

**旧C448及C256/M32 smoke继承range16量化，不能称原精度或质量最优。** 新对照原量化SHA为35ef6de51d90e057f69dfbb87d35c51dee1a85b435f3f6ab5a8d0c10f6afce6d；旧range16为65e84a1fa8d4941bbc082b274dab1b67d2929ace2089edf354d0f232bf650921。只看导出data相同会漏掉这项变化。

## 输入和范围

诊断：system正文59+模板5=64；动态正文256+模板8=264；prompt328；每次reset、单独准备system，仅reuse64/new264；固定反馈输出4token。每配置重复3次，顺序为原量化、原量化tail8、原量化复测、range16。每份logits 2426784字节（4×151674×4）。诊断时间不作为纯性能数据；本轮无语音/RAG并发。

## 结果

- 控制器和板端rc0，4个worker正常关闭，driver均0。
- 原量化、tail8、原量化复测共9份全词表logits全部逐字节相同、finite。证据见ANALYSIS.json；这是一个长输入重复诊断，不是普遍无损保证。
- range16的3份logits SHA各不相同，首预测3837/20002/3837，重复一致性失败。变化定位到替换L2/L3的量化图路径；尚不能确定SDK内部的具体根因。
- 6条自然中文：原量化tail8与前后原图均6/6 token序列相同；range16仅2/6相同。它出现复述输入、格式改变等问题，不能纳入部署最优。原图也有既有保守静止输出，序列相同不等于动作正确率。
- 末尾SwapUsed约2660MiB，为整机累积状态；无连续swap监测，不能声称本轮无换页或归因给候选。
