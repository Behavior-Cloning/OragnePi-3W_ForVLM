# 实际 NPU 首块异常值诊断

范围：Intern NPU 文本、固定 system64/128（正文59/123+模板5）、动态正文64/256（模板另8，新增72/264）。这里只用两条成本样例定位误差；没有语音/RAG并发、视觉或物理动作，不作延迟成绩。

完整模型 I16 候选比同 C1280 原图首 token 快约33%，但完整词表 logits 有明显漂移、自然回复有旧指令复述，不能晋升。实际采集 fused block1（层2/3）的11输入和5输出，时点为group完成后、任何本轮KV追加前。对照未插桩原binary与插桩版，每个配置四步完整词表 logits 实际逐字节相同，4组均通过；8次模型释放后driver0，136个捕获文件SHA及finite通过。

68个窗口按原图/候选、两条输入分为9/25/9/25。进入block1的hidden在34个原/候选配对中均完全相同；首chunk全部11输入也相同。首chunk候选输出hidden相对L2误差99.3948%、maxabs1893.5625；同输入已直接出现差异。原/候选层2 K/V相同，层3 K/V已经不同，后续窗口的比较受历史污染，不能当作独立同输入误差。

在这些实测外部输入上运行原图FP32解释器，估计首chunk首行down中间值：b0输入峰2035而候选范围约±8、输出峰913而范围约±2；b1输入峰1181而范围约±16、输出峰968而范围约±4。4个pos0窗口重复出现相同越界，其余64窗口没有这四项的估计越界。**内部中间值是FP32推算，不能写成NPU内部量化张量的直接测量。**

这支持首system chunk异常值导致候选饱和的假设，但尚未证明它解释全部质量变化。下一项因果诊断只在pos0使用原FP16 block，后续保留I16；分别比较group/非group原图控制、非group候选、首块修复候选。必须先看完整logits及自然回复能否恢复，不能以单块更快直接晋升。固定缓存构建计时与热动态请求计时分开。

原始证据：results/actual-npu-range-r1，analysis.json，INDEPENDENT_CAPTURE_AUDIT.json。捕获及源码权威版本在Windows仓库。
