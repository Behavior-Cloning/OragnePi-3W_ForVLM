# Native RMSNorm C512/M32 L0/L1 screen

Compiled only; no board performance or accuracy evidence. The pinned SDK6.30.22 exposes RMSNormalize as rmsnormalize(axis,eps), learned scale coefficient. Four original max-scaled decompositions replaced with native op at same gamma and epsilon (~1e-6), preserving the original output quantizer and other projections. In real arithmetic, max-scaling cancels; in finite precision, accumulation/overflow/underflow may differ. Native kernel numerical stability must be tested before any wider deployment. attention API has only two explicit inputs and is not verified as causal masked GQA SDPA; no FlashAttention support claim.

Generated C emits4 VSI_NN_OP_RMSNORM; this is not proof of physical engine or speed. controller_native_rms.py prepares original/native/original for canonical M32/history128 plus synthetic maxabs4096 hidden stress; other input bytes untouched. No real language or natural quality claim from synthetic stress. Board execution remains pending independent audit and release of current full-model locks. Whole goal system64/128 and body64–256+8, prefill and TTFT<=100ms remains unachieved.

Independent audit found actual coefficient representation changes: SDK native scale is FLOAT32 whereas original scale was I16/DFP; one of3584 gamma values differs by2.813339e-5 after original quantization. The source gamma arrays were copied, but exported values are not all equal. Native epsilon is also a singleCfloat parameter, whereas the old stable decomposition quantizes/intermediately rounds its epsilon-root operations. This is explicitly a precision candidate, not same numerical path.
