# Compact past128 probe 增量源码审计

**通过本次独立探针源码增量检查；尚无板端资格结论。** 审计只读 Windows/WSL 文件，无编译器、SDK、板卡或模型调用。

5份源码中仅 `tensor_probe.c` 改变：past context 白名单从512放宽为128或512，并校验全部11输入和5输出元素数。精确逆替换该小段可复现旧源码SHA；另外4份源码逐字节同。编译命令除输入/输出文件路径外与原命令完全相同，返回码0，实际新binary SHA `18b29578182bf1067512008ad914897a7639bcdba6d89dff2bc4bee173f4c1e4`，61,832字节。原binary保留。

M256/past128可被接受：past是历史输入长度，并不要求query≤past。输入按顺序检查hidden `M×896`，四路KV各 `2×C×64`，两路mask各 `7×M×(C+M)`，四路RoPE各 `M×64`；五输出为hidden `M×896`及四路KV各 `2×M×64`。C128/M256输入F32为6,946,816字节，原C512/M256为13,238,272字节；输出同为1,441,792字节。整数除法后的全部精确元素数检查会拒绝不能整除的隐藏/历史尺寸。

转换、缓冲区绑定、warmup/repeat、数值检查、执行与释放均未改。计时仍只围绕 `vip_run_network`，显式输入flush及输出invalidate在计时外。新result中的`capacity=128`只表示past输入物理长度，不代表完整缓存只有128或总可处理token上限128。

边界：本探针自身不验证移除槽位是否无效；后续fixture/controller必须核全部被移除KV和mask、保留128有效历史、全部256query、绝对RoPE位置。不可对旧flat输入直接截字节；需分别按张量轴gather。元素数校验不能替代形状轴/dtype/端口顺序审计。有限值−10000不等于数学负无穷，候选数值仍需实际核查，不凭掩码语义声明bitwise。

完整runtime的KV存储容量仍须足够，例如512；compact图的past容量128是独立概念。真实有效past超过128时必须回退足够容量路径，不能丢历史。此源码审计不证明完整prefill/TTFT、自然任务质量或100ms目标。
