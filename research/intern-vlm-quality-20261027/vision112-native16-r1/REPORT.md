# 112×112 原生合并16 token：性能与 VQA

2026-10-27。不是官方发布的112准确率，而是我们沿用官方2×2 pixel shuffle＋原projector权重的低分辨率适配实验；仍存在位置编码插值与分辨率分布变化。移除先前keep64通道重复适配。64 patch+CLS进入ViT，原生合并后16×896视觉向量。

## 板端 CPU 视觉性能

CPU6/7两线程，同binary，同图，两图交替；每phase1预热＋10热样本。编码＋投影，不含JPEG解码/resize/normalize、加载、文件读写、LLM；不是NPU完整塔。

|方案|热推理P50 ms|范围 ms|加载 ms（单次）|
|---|---:|---:|---:|
|fp16-before|907.183|906.933–907.748|437.188|
|q8-stock|981.516|981.359–981.759|249.548|
|q8-repack|475.248|474.954–475.535|893.243|
|fp16-after|910.502|910.245–910.937|451.990|

优化Q8约475ms，旧112 keep64优化Q8约487ms；本次保留原投影结构且输出token更少，不能把全部差异当算子优化。同轮FP16前后约907/911ms。44次均正确输出16×896且finite、4进程正常关闭；温度传感器最大59.396°C，全phase最大RSS606.15MiB（含FP16，不是Q8专属）。两图Q8相对FP16特征relative L2约7.2–8.3%，不是准确率。

## VQA结果与对照

板端生成视觉向量→WSL CPU Q8语言参考模型，贪心解码，每题清空KV、最多32输出token。不是板端NPU VLM整链路计时。

|视觉配置|核心事实答对|
|---|---:|
|112 FP16 原生16|0/6|
|112 Q8 原生16|0/6|
|112 优化Q8 原生16|0/6|
|224 FP16 原生64，同程序复测|5/6|
|448 FP16 原生256，同程序复测|6/6|

小样本只是2张开发图片，不能视为通用VQA准确率。224把木板错答为树枝；448答木头。112在动物类别题回答“图片中没有动物”；鼻子/耳朵题列举不同物种的一般颜色，不是对当前图像的正确回答。零视觉向量控制同样答无动物，但不能因此证明112向量没传入：输出确为14336有限浮点，两图RMS约0.568/0.555；正常224/448对照可辨图。当前证据不能区分112视觉适配缺陷与低分辨率/少token分布变化，需要与官方框架同输入逐层比对。

故移除自制keep64投影适配后质量问题仍存在；不能把原先失败全归因于通道重复，也不能归因于Q8量化（FP16也失败）。112仍不晋升可用默认。

Token口径：system正文30＋模板5＝35；图像16＋问题5–9＝动态内容21–25；动态模板及图像边界11；总输入67–71。本参考每题reused=0，实际new=总输入，不是system缓存性能测量。输出上限32；逐题实际输出见VQA_AUDIT与答案JSONL。224/448对照总输入相应增加48/240。
