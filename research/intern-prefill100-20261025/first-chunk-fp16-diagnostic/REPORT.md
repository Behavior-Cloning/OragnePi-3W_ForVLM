# 固定system首块保留原计算：因果诊断

结论：首system chunk异常值是此前整模INT16明显漂移的重要原因。仅在位置0的第一个16-token块保留原层2/3计算，后续仍用INT16，四个定位案例的自然回复均恢复到原图。**不代表整体质量通过，也没有新的有效性能成绩。**

输入：固定system64/128＝正文59/123＋模板5；动态正文64/128/256，模板另8，实际新增72/136/264。4条案例为两条成本输入＋同一后退场景两种system长度，独立场景数少，均为开发回归。诊断输出4固定feedback token；自然输出上限32，恢复后实际含EOS为3/5个。无动态KV复用，只复用system。原图group/非group、I16非group、首块修复I16非group四组同输入。

|案例|原INT16 logits相对L2|首块修复相对L2|修复后自然回复|
|---|---:|---:|---|
|S64 / D64 成本样例|46.50%|2.89%|点头回应|
|S128 / D256 成本样例|49.75%|2.92%|点头回应|
|S64 / D128 后退|51.11%|2.89%|后退两厘米|
|S128 / D128 后退|52.97%|2.99%|后退两厘米|

上表logits只比较4步相同固定feedback，完整151674词表；自然生成不同历史后的logits不当作同输入误差。修复后16/16 top1同原图，4/4自然token序列同原图。两个后退案例从“用户开始说向前挪。”恢复正确方向和距离，但原图本身未表达“缓慢”，因此属于恢复基线部分满足，不能称指令全满足。

独立检查32结果＋32system准备共64份logits实际SHA/finite/argmax；4次close driver0，8次首块替换。原group/非group控制8份结果logits逐字节同。第一块替换在system构建阶段进行，热动态请求不包含它；本诊断开启完整logits转存，因此耗时不能冒充热TTFT。

后续group热路径首次尝试失败：destroy_group后网络仍被SDK视为group成员，返回-9。失败目录first-chunk-grouped保留，fulli16-firstfix预备矩阵明确禁止启动。新suffixgroup-firstfix采用永久分组，前两个块单独提交、后十块固定group，当前仍待板端数值验证及公平性能评测。
