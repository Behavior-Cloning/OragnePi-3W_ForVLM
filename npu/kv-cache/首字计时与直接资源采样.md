# 首字计时与直接资源采样

2026-10-13，下一轮攻关的测量修正。旧原始结果保留，新字段与旧HTTP首字并列，不能把计时口径变化当作提速。

## 引擎首token与首个可见文字

核对项目固定的llama.cpp源码包`d81235049384534c167caea52b85a694f6103d14`：

1. `tools/server/server-context.cpp`第3354行在slot开始处理prompt时调用`update_prompt_start()`。
2. 同文件第4190行附近执行`common_sampler_sample()`，接受采样结果并同步context；当`n_gen == 1`时调用`update_prompt_last()`。
3. `tools/server/server-common.h`的`t_prompt_ms()`返回`(t_prompt_last-t_start)/1000`。因此在本固定版本、当前非推测生成路径中，最终`timings.prompt_ms`已包含新增prefill和第一个token采样，可作为引擎TTFT。
4. `process_token()`先检查UTF-8完整性，再调用`send_partial_response()`。部分token已算出但尚未拼成完整字符时，不会上报SSE事件。客户端首事件与引擎首token不是同一指标。

源包位于`data/llama-d81235049384534c167caea52b85a694f6103d14.tar.gz`，部署脚本固定该版本。CPU结果另存可执行文件SHA256；若更换引擎版本或启用推测解码，必须重新核对上述计时定义。

均为完整32层、固定128次预测、5轮中位，历史KV驻留。尤其1024＋32：统一引擎计时后两者接近，不能继续用旧HTTP口径声称NPU首字更快。真实网页还需统一HTTP/SSE接口后另测首个可见文字。

`cpu_incremental_reference.py`新增`engine_ttft_seconds`，保留`ttft_seconds`和`first_visible_text_seconds`。同时把总响应截止点移到响应读取完成时，避免把等待采样线程退出算进响应；CPU进程时间也在这个边界读取。旧总响应未被静默重写。`report_thermal_matrix.py`基于原始`prompt_ms`给已完成数据补充引擎首字对照。

## 直接资源计数

新增`resource_sampler.py`，同时用于CPU和NPU运行器：

- 直接读取`/proc/stat`，记录整机及每核CPU原始tick、区间busy%与iowait%；单核百分比与整机百分比分开。
- 记录`/proc/meminfo`可用内存、swap存量、页缓存、Dirty/Writeback，`/proc/vmstat`实际swap换入换出及页错误增量。
- 记录待测进程CPU时间、RSS、约每5秒一次PSS、页错误和`/proc/PID/io`；不会误把网页后台Qwen进程当测试模型。
- 从`/proc/diskstats`记录整块物理磁盘读写量，不把分区与父设备重复相加；记录CPU/NPU频率、直接温度和NPU驱动分配。
- 所有采样带单调时钟和自身耗时。仅区间起止均在响应内时才纳入统计，排除预热/准备和释放内存阶段，披露覆盖秒数与边界缺口。约1秒采样不能保证捕获峰值。

实机首批确认：500M1024＋128中温，CPU整机约26.52%，NPU约1.11%；有效覆盖约7.40秒和9.23秒，覆盖区间swap换入/换出均为0。更早的swap已用量不为0，与“当前未换页”并不矛盾。完整新记录见[三温档全深度对标](三温档全深度对标.md)。

实板兼容修正：板端没有`/proc/PID/io`，direct-v1因此还丢弃了本可读取的进程内存字段；direct-v2将I/O可用性与CPU/RSS/PSS解耦，实板已采到PSS。旧缺失值不追填。另发现direct-v1/v2的`npu_driver_bytes`正则误读分配次数；direct-v3要求从第一列0x十六进制字节值解析，修复已加入真实格式回归检查。报告始终采用C运行器正确的`driver_allocated_bytes`，旧动态字段不进入内存结论。详见[直接负载对照](CPU与NPU直接系统负载对比.md)。

这不是功率计，也不提供可靠的NPU busy%或全模型DRAM带宽。硬件算子profiling和电功率测量另列，不能把CPU占用下降直接转换成省电比例。

## CPU Q8搜索与温度记录

`run_cpu_q8_search.py`对512/1024历史、64新增先筛线程/绑核，再筛Flash Attention和prefill参数；每配置预热一次、初筛两轮，decode/端到端入围配置五轮确认，并扩展32/128新增。权重保持Q8_0。与冻结轨迹不同的配置标记“需要重新对齐和质量验证”，不是自动判定模型质量差；在完成验证前不把它当同轨迹胜负依据。

新采样记录位于`npu/results/cpu-q8-search-20261013`。初筛不是最终最优CPU验收；仍需独立质量门槛与正式逐场景比较。

首次500M1024＋64的6线程尝试，在下一轮历史准备中达到80.948°C，温度保护终止独立测试服务，失败结果保留。后续搜索把准备起温降到50°C以下，并在首次非流式轨迹采集前也做温控；正式响应仍55–<65°C起测。计时前的冷却不清除KV、不降低CPU频率上限。80°C保护覆盖独立测试服务生命周期；若触发，记录无有效成绩，不将截断运行计入排行。高温起测档仍暂停。

新增计数器测试覆盖单核/整机分母、iowait、计数器回退，以及预热和收尾区间排除；采样器已在真实CPU/NPU测试运行。温控与断点续测原有8项检查通过。
