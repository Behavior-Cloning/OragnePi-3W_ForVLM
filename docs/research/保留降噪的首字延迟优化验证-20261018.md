# 保留降噪的首字延迟优化验证（2026-10-18）

## 结果

在橘派 Zero 3W 上保留 GTCRN 降噪，配对测试 3 轮。把音频前端与 Paraformer 从 A55 单线程（CPU 2–3）移到 A76 双线程（CPU 6–7），并将 Silero VAD 静音端点从 500 ms 调至 250 ms。

| 指标，中位数 | 原配置：降噪开启 | 优化配置：降噪开启 |
|---|---:|---:|
| VAD 判停后到 ASR 完成 | 0.627 s | 0.117 s |
| ASR 完成到 LLM 首段文本 | 1.125 s | 0.917 s |
| VAD 判停到 LLM 首段文本（逐轮相加后取中位数） | 1.758 s | 1.025 s |
| 指令音频开始到 VAD 判停 | 5.263 s | 4.666 s |

优化配置保留了三条测试语句的相同 ASR 文本。上述 LLM 在板上以 CPU 运行 Qwen2.5-1.5B Q4；这不是 NPU LLM 链路。

## 对“真实说完到首字”的判断

本轮是录音回放，没有人工标注真实语音结束点。VAD 使用 250 ms 静音端点，因此按“语音结束后需等满 250 ms 才判停”估算，真实说完到首字约为 **1.28 s**（1.025 + 0.25）。所以已经接近，但还没有证明达到 1 秒。要稳定达到 1 秒，需要把 LLM 首段延迟进一步降到约 0.65–0.75 s，或在用户说话期间用稳定的流式 ASR 提前启动 LLM。

## 边界

每种配置只有 3 轮，测试为合成唤醒词加公开 AISHELL 录音，非家庭麦克风实时对话。优化项同时改变了 CPU 核/线程数和 VAD 端点阈值，结果不能归因于单一变量。降噪模型始终开启；A76上的GTCRN帧处理预算需在家庭噪声与LLM并发时再验证。LLM首字采用 HTTP 首个非空文本块的时间，不等于 tokenizer 内部首 token 时间。

逐轮原始记录：`results/audio-denoise-opt-20261018/summary.json`。


## 端点阈值复测：250 ms 与 100 ms

保持 GTCRN、A76 CPU 6–7、Paraformer 双线程、相同短回答提示不变，再配对测试三轮；仅将 VAD 静音端点由 250 ms 降到 100 ms。

| 指标，中位数 | 250 ms | 100 ms |
|---|---:|---:|
| VAD 判停后到 ASR 完成 | 0.116 s | 0.116 s |
| VAD 判停到 LLM 首段文本 | 1.031 s | 1.025 s |
| 估算真实说完到首段文本 | 1.281 s | 1.125 s |

250→100 ms 只节省约 0.15 s，首字延迟仍受 LLM 首段等待主导。两组 ASR 都有同一条专名样本识错（朱圣祎→朱胜伟），其余两条正确；三条样本不足以评估短端点造成的截句风险。测得回合末温度最高约 52.0°C。结论：目前降噪开启的最佳测量值约 **1.13 s 真实说完到首字估算**，尚未达到且未验证稳定达到 1 秒。后续需要测真正流式 ASR 在讲话期间何时形成稳定 partial，并评估能否安全地让 LLM 预生成。

端点阈值配对逐轮记录：`results/audio-denoise-opt-20261018/endpoint-sweep-summary.json`。
