# M256 原始诊断独立审计

结论：**诊断证据完整；M256 的 softmax NN busy 计数存在明显非线性增长。** 这可支持继续做分块候选实验，但不能证明某个引擎的耗时占比，也不构成整模 TTFT 或 100 ms 目标验收。

独立重算原始二进制记录：M32 为 2,986 条、M256 为 28,462 条，每条 128 字节；VNPD v2、target `0x1000003b`、单网络单核，所有字段与 SDK 段解析输出逐项一致，没有计数器溢出。原始 NPD、F32、日志、配置均保留在 Windows，回收归档每个成员逐字节核对通过。两份实际输出均为 1,441,792 字节，五端口 finite，且与此前无诊断原图输出逐字节相同。两次释放为 0，前后 driver 为 0；控制器 rc0/meta complete。

| 指标 | M32 | M256 | M256/M32 |
|---|---:|---:|---:|
| Query 行数 | 32 | 256 | 8× |
| 完整 softmax key 轴 | 544 | 768 | 1.412× |
| 两层 softmax 标量元素数 | 487,424 | 5,505,024 | 11.294× |
| Softmax NN busy cycles | 1,069,254 | 111,509,399 | 104.287× |
| 全部观测 NN busy cycles | 10,030,853 | 207,039,008 | 20.640× |
| Softmax 占观测 NN busy 计数 | 10.660% | 53.859% | 非 wall-time 占比 |

Softmax 按 query 行归一化增加 **13.036×**；再考虑 key 轴扩张，按标量元素归一化仍增加 **9.234×**。其他增长较大的观测计数包括 reducemean/reducemax，每 query 行约 8.1–8.2×；这同样不能直接折算为总耗时。M32/M256 来自不同轮单次 NPD capture，无重复计数置信区间。

映射使用两份各自与原 NB SHA 完全相同的 trace export，并独立从生成 C 的每个节点注释/UID 重建类别。两层 softmax 映射至 UID50，profile nodes 207/269；UID 在两层复用，因此保留两个候选源节点名，不猜具体 b0/b1 归属。trace 无 target 字段，不能据此声称 CPU fallback 或硬件引擎占比。相同 trace SHA 只表示节点拓扑映射相同；图形状由各自生成 C 单独确认。

IO 模式 3 次预热、5 次诊断，run 中位数 **210.242 ms**，flush+invalidate 中位数 **0.046458 ms**（wall 的约 **0.0221%**）。NPD 模式 0 次预热、1 次诊断，带计数开销 API 为 **268.991 ms**。两者均 `timing_eligible=false`，不能替代既有纯 API 基准，也不能将 run 减去 NN 计数折算所谓 host/其他引擎时间。

4.34 秒诊断窗口共 16 个资源样本：最高 **39.866°C**，最低 MemAvailable **3838.34 MiB**，swap 919.75 MiB 不变且换入/换出增量为 0；全八核 CPU 加权平均约 **7.67%**。这仅是短诊断观测。tmpfs 最低剩余 2,439,761,920 字节，启动 staging 与 1 GiB+100 MiB / 额外 256 MiB 内存预留断言通过。暂存仍由父控制器管理，审计未清理或访问板卡。

范围仅 L0/L1 融合两层、固定 canonical 输入、FP32 派生 history128，无语音/RAG并发或实际 NPU KV 历史，不代表完整 24 层、自然任务正确率或长时间稳定性。后续按非归约 query 行切块可以保持数学 softmax 语义，但仍需完整量化/端口/实际数值与纯计时验证。
