# 长动态输入语义留出集：人工金标准 v1

本目录只冻结输入和评分规则，尚未运行任何模型，不接入正在运行的 fullconv harness。权威文件是 `inputs.json`。`scenes.source.json` 保存 12 个原始场景及背景／最后要求的分段，`build_fixture.py` 可重新生成 JSON，`validate_fixture.py` 独立重编码并生成 `token-validation.json`。

## 输入与统计口径

- 12 个新编写的家庭／桌面陪伴情景；动态正文 64、128、192、256 tokens 各 3 条。每条分别配相同的旧 system-64、system-128，因此共 24 次呈现，但只有 12 个独立场景。
- 两个 system 的文本、token IDs、哈希均逐字保留父目录 `inputs.json`：正文分别 59／123 tokens，system 模板 5 tokens，缓存总前缀 64／128。system-128 原有重复指令及标点仍在，不能声称两个 system 仅缓存长度不同。
- 新动态正文全部是完整自然语言，**没有截断、重复填充或标点补长**。为精确长度所作的用词调整和家庭背景补充已冻结，未参考模型输出。
- 正文以外的 user／assistant 模板占 8 tokens。实际新增 prefill 为 **72／136／200／264**，总 prompt 最长 392。不得将正文 256 写成实际新增 256。
- 本集拟用于无固定反馈的自然生成；固定 32 步性能实验是另一种契约。此处不启动实验、不修改后续模型配置。
- holdout 只表示新编写、模型运行前冻结、未用于现有输出调优；不声称与预训练数据可证实不重叠。各长度使用不同情景，适合相同样本的候选／基线配对比较，不用于证明长度单一因素的因果影响。

## 机器人与状态前提

只允许头部、双臂、腰和低自由度底盘动作；底盘可前后左右平移及转弯。没有眼睛、手指、屏幕、表情显示，不包含开发、查文档、定时、联网或其他 skill。语境中的电视、故事、过去讨论是输入背景，不是要实现的新能力。

正文明确给出的姿态、障碍和安全空间是 harness 提供的**文本状态假设**，不是本次已通过视觉、音频或传感器验证的事实。所有输出仍是 mock 动作，不允许据此驱动物理电机。底盘动作期间“头、臂、腰不动”指相关关节保持相对机身姿态，不要求它们在世界坐标不动。

## 评分方法

对完整原始回复做人工语义判断，**不以固定字符串、关键词命中或 A/B 输出一致作为正确标准**。不替模型补出缺少的左右、范围或安全条件，同义词可通过。保留输出全文及对应输入／输出 SHA，先冻结本规则，再盲化候选名评分；复审分歧记录原因。

分别记录：

1. 硬件可执行性：是否只需要已声明的部件和能力。
2. 硬约束兼容性：是否违反禁止动作、当前障碍、取消或最终纠正要求；无法判断记 unknown。
3. 最后指令完成度：complete／partial／not_done／unknown。方向、主体和终止姿态都属于任务。
4. 格式：是否只有一个动作短语。解释、回答问题、多动作列表单独记格式失败。

总体语义类别：

- `pass`：完成最后有效要求，满足硬约束；同义短语可接受。
- `safe_underresponse`：可执行且没有冲突，但未完成所要求动作，例如应点头却保持静止。**这不是“完全不相关／不能执行”**。
- `compatible_partial`：安全且方向、主体正确，但细节缺失或替换，不足以认定完成。
- `underspecified`：缺关键主体、方向或终点，无法判断兼容性，不能自动当作无冲突。
- `conflicting_or_infeasible`：违反禁止／纠正／状态约束，或要求不存在的硬件、抓取物品等能力。
- `unjudgeable`：空回复、乱码或不能解释为动作；同时记格式问题。

同时报告完成率、明确冲突率、安全未完成率和 unknown 率。不要把唯一标准动作的命中率叫“所有可执行动作的相关率”。保持静止在两个 hold 场景是 pass，其余十个通常是 safe_underresponse。

一次点头等未明示次数的常用单动作短语，可按一次理解；若明确写反复则不满足一次要求。不涉及指关节的“抬手招呼”可理解为抬臂，不因俗称“手”判硬件不可行；缺左右仍按关键方向缺失评分。输出“不要摇头”是禁止说明，不是执行摇头，必须判断否定作用域。

## 逐场景金标准

| 场景 ID（两种 system 共用） | 必须表达的最终动作 | 可接受示例（非穷举） | 重点不接受／区分 |
|---|---|---|---|
| d64-return-home-nod | 轻轻点头一次 | 轻轻点头；点头回应 | 摇头、靠近、摆臂冲突；静止安全但未完成 |
| d64-greeting-right-arm | 低幅度抬机器人右臂招呼 | 右臂轻抬招呼；低幅度抬右臂 | 左臂／双臂、碰杯、移动或转头冲突；抬臂未指左右则欠明确 |
| d64-edge-hold | 全身保持静止 | 保持静止；全身不动 | 前后左右及转弯不可；点头或摆臂也违反全身静止 |
| d128-waist-bow | 以腰小幅鞠躬一次 | 轻轻弯腰致意；轻轻鞠躬 | 抬头代替弯腰不通过；点头不是所要求的腰部动作；静止安全但未完成 |
| d128-head-left | 头部小角度左转 | 头部轻轻左转 | 右转或底盘左转冲突；向左转未指头／底盘则欠明确 |
| d128-base-back | 底盘缓慢后退两厘米 | 底盘缓慢后退两厘米 | 前进、侧移、转弯冲突；仅后退方向正确但缺缓慢／距离时记 compatible_partial |
| d192-lower-arms | 已抬起的双臂缓慢放下至自然垂下 | 双臂缓慢放下；双臂收回自然垂下 | 再抬起或挥臂冲突；只放一臂未完成；这是当前姿态依赖 |
| d192-base-turn-right | 底盘原地小角度右转 | 底盘原地向右微转 | 左转或伴随平移冲突；未明确底盘／原地时欠明确或部分完成 |
| d192-child-near-arm-hold | 全身保持静止 | 保持静止；全身不动 | 挥臂、点头、弯腰或绕行都冲突；旧挥臂计划已取消 |
| d256-head-neutral | 从略低姿态缓慢回正至中立 | 头部缓慢回正；抬头回到中立 | 抬头回正可通过，不能只凭抬头字样误判；单写抬头无终点则欠明确；抬过中立、继续低头或反复点头冲突 |
| d256-left-arm-correction | 自身左臂低幅度抬起招呼 | 左臂轻抬招呼 | 右臂／双臂、高举或抓物冲突；不能按观察者镜像交换左右 |
| d256-base-left | 底盘缓慢向自身左侧平移两厘米 | 底盘缓慢左移两厘米 | 右移、前后、转弯冲突；左转不等于左移；缺距离／速度记 compatible_partial |

示例只用于解释规则，**不要送入模型 prompt**。模型只收到原 system 和该条 body；gold、背景分段注释与本文件都是评审元数据。

## 下一轮仍需 root 决定的事项

- 先审这些自然长文本及规则，再决定接入哪个候选／基线；当前 fullconv 不受影响。
- A/B 使用同一份冻结输入及缓存策略，无动态 KV 预计算；不能按输出改文本或金标准。
- 自然回复长度、终止原因、实际 token 数及完成度分别报告；不同自然输出长度不能直接充当公平 decode 吞吐对照。
- 只有 12 个任务，没有家庭噪声、真实麦克风、视觉定位、物理动作、安全闭环或长期稳定性验证。输出正确不等于真实执行已验证。
