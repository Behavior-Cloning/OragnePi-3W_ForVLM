# Orange Pi Zero 3W 配网程序设计说明

日期：2026-10-15。状态：仅设计，尚未实现或验证AP/BLE功能；未修改开发板网络。

## 目标

服务对象是当前A733 / 6GB Orange Pi Zero 3W桌面陪伴机器人。换办公室或Wi-Fi后，无需显示器、拔TF卡或预先知道板端IP，即可用手机或Windows电脑配置网络。板端独立运行配网服务，不依赖开发电脑常开。

建议第一版实现Wi-Fi热点网页配网；第二版增加BLE入口，共用同一套网络状态机和配置管理逻辑。

## 官方硬件依据与边界

2026-10-15查阅[Zero 3W官方产品页](http://www.orangepi.org/html/hardWare/computerAndMicrocontrollers/details/Orange-Pi-Zero-3W.html)，规格明确列出：

- Wi-Fi 6。
- Bluetooth 5.4（BLE）。
- 无线连接支持外接天线。
- 40-pin扩展，包含GPIO/UART/I2C/SPI/PWM，可作为后续外接配网按钮的基础。
- 支持Ubuntu、Debian等操作系统。

[官方下载页](http://www.orangepi.org/html/hardWare/computerAndMicrocontrollers/service-and-support/Orange-Pi-Zero-3W.html)提供Ubuntu/Debian镜像入口；本次英文页面虽列出User Manual Downloads，但没有找到可点击的有效手册下载链接。

因此上述只确认硬件基础，**不证明当前Ubuntu驱动支持AP热点、AP/STA并发、BLE外设广播/GATT服务或稳定的Wi-Fi/蓝牙共存**。未确认无线芯片具体型号，不用Zero、Zero 3或Zero 2W的资料替代Zero 3W结论。

## 第一版：热点网页配网

用户流程：

1. 开机尝试已保存的Wi-Fi；持续连接失败约90秒后进入配网模式，时间可配置。
2. 板子开启`OPI-Setup-xxxx`热点，使用每台设备独立密码，随设备提供标签或二维码。
3. 手机或电脑连接热点，打开固定网页，例如`http://192.168.50.1`。实施时确保该子网不与目标网络冲突。
4. 选择扫描到的网络或手工输入SSID，输入密码，提交连接请求。
5. 页面提前说明热点可能断开；板子尝试新网络。
6. 成功取得IP后保存配置并退出配网；失败或超时则恢复热点，显示具体错误，允许重试。

第一版不依赖AP/STA并发。若无线驱动不能同时开热点和连接路由器，则先停热点再试连；成功后手机需切回目标网络。网页不能在已经断开的连接上实时收到结果，不承诺提交页面自动显示成功。

热点优先考虑2.4GHz，以兼容常见客户端，实际频段和信道必须按驱动能力及地区规则选择。配网热点频段与板子连接目标路由器的频段是不同设置，不能由此推断仅支持2.4GHz目标网络。

### 页面功能

- 附近SSID、信号强度、安全类型；网络扫描受AP状态约束时，提供进入热点前的扫描结果与手工输入。
- 隐藏SSID输入、密码显示/隐藏、连接状态与错误原因。
- 保存多个网络、设置连接优先级、查看当前IP。
- 提供重试与返回，不要求用户SSH修配置。
- 自动弹出配网页仅作便利功能，固定IP入口始终保留；不劫持HTTPS或要求用户忽略证书警告。

### 状态和回退规则

| 状态 | 行为 | 下一步 |
| --- | --- | --- |
| 启动重连 | 按优先级尝试已保存网络，有总超时 | 已连接或进入配网 |
| 配网热点 | 提供网页、DHCP与必要DNS服务 | 用户提交新配置 |
| 试连 | 保存候选配置，保留旧配置，关闭热点试连 | 成功确认或恢复热点 |
| 已连接 | 记录IP与网络状态，正常运行机器人 | 短断线先重连，不立即切模式 |
| 回退 | 恢复配网入口，解释认证失败、找不到网络或DHCP超时 | 等待用户重试 |

以Wi-Fi接入并取得有效IP作为连接成功的核心条件，外网/DNS可用性另显示。没有互联网不等于Wi-Fi失败，离线机器人不应因外网断开反复切热点。连接配置应原子保存；试连途中断电，重启后也必须能重连或恢复配网。

## 第二版：BLE配网

板子进入配网模式后广播设备名；客户端通过BLE GATT发送SSID和密码，板子连接目标Wi-Fi，并通过BLE通知状态及IP。蓝牙无需承担模型传输或聊天媒体数据，仅负责配置与少量状态。

板端拟使用BlueZ的广告和GATT服务接口。BLE版本号本身不能证明当前驱动支持所需外设角色，必须测试。

客户端方案：原型可用BLE调试工具验证协议，产品化采用手机App或Windows客户端。不能承诺同一个网页在所有Android、iPhone和Windows浏览器上均能蓝牙配网；Web Bluetooth支持并不统一，Windows电脑还需可用蓝牙硬件及驱动。

配网协议应包含请求ID、SSID、凭据、安全类型、提交指令、状态通知和超时。处理UTF-8中文SSID、分包、断连重试与重复提交；不把一次BLE写入的长度假设为足够容纳所有字段。使用设备验证与受保护的连接传输凭据，不能仅凭可发现的设备名授权修改网络。

## 软件结构

| 模块 | 职责 |
| --- | --- |
| 网络适配层 | 沿用系统已有网络管理器；如为NetworkManager，通过其接口管理连接，避免多个服务争抢无线接口 |
| 配网状态机 | 超时、试连、失败回退、断电恢复、多个已存网络 |
| Web入口 | 热点内的本地配置页面和状态接口 |
| BLE入口 | 可选GATT服务，调用同一状态机 |
| 配置存储 | 限制凭据文件权限，原子更新，不在日志和Git中记录密码 |
| 设备发现 | 尝试提供`opi-minibot.local`，同时保留IP查询方式；不保证企业网络支持mDNS |
| 手动触发 | 已联网时的网页按钮；后续可加GPIO实体按钮，先核对具体引脚复用，避开风扇和现有外设 |

配置接口仅在配网接口或经认证的管理入口开放，不默认暴露给所有网络客户端。热点使用独立密码；设置配网开放时段和重试限制，避免永久开放无认证入口。SSID/密码按数据传递给网络服务，不拼接成Shell命令。

## 实施前检查与验收

首先只读检查无线设备/驱动、固件、`iw list`的AP支持与valid interface combinations、网络管理器，以及BlueZ控制器和广告/GATT能力。不要在正在执行LLM测评时切换网络。

确认能力后，在有恢复手段的条件下测试：

- 正确密码、错误密码、隐藏SSID、中文SSID以及扫描不到的网络。
- DHCP超时、路由器断电、有局域网但无互联网。
- 配网途中断电，重启后的配置恢复。
- 多网络切换、回旧办公室自动重连。
- 手机/Windows访问固定地址，未自动弹出页面时仍能使用。
- BLE方案额外测试断连、分包与Wi-Fi共存。
- LLM运行期间的配网资源开销和连接稳定性；配网结束后无持续高CPU占用。

第一版优先普通个人密码Wi-Fi。企业802.1X账号/证书、网页登录认证网络另列需求，不假设只输入SSID和密码即可支持。公司网络若隔离客户端，配网成功仍可能无法访问机器人网页，需单独显示“已联网但设备访问受限”，不能靠mDNS绕过隔离。

若板载AP驱动不可用，可评估BLE优先或已确认Linux AP支持的USB无线网卡；不要在未测试之前要求用户购买额外硬件。
