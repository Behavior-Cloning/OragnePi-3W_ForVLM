# 256M、500M 与 1B 板端对比

评测日期：2026-10-09。硬件为 Orange Pi Zero 3W / A733 / 6GB，TF 启动。
500M 指参数规模，不是 500MB 文件。各候选权重已在板端下载并按固定版本 SHA-256 校验。

## 结论与适用场景

当前网页 <http://192.168.88.29:8080> 已选择 InternVL3-1B-Instruct，优先让用户体验中文连续对话。
页面提示首次看图较慢；256M、500M 均保留，便于按速度需求切回。

- SmolVLM-256M：最省内存、英文解码最快，适合简单英文图片描述；中文闲聊、记忆和推理很弱。
- SmolVLM-500M：英文描述可用，但本次中文仍答非所问/乱码，未解决用户提出的中文连续对话问题。
- InternVL3-1B-Instruct：中文回应和会话内记忆明显改善，但首次图片处理慢，仍会算错简单题、编造细节。
  不能视为主流云端 VLM 的等价替代。

这里的 1B 是官方 ggml-org 提供的 **InternVL3-1B-Instruct（SFT）** GGUF，
不是标准 InternVL3-1B 的 MPO 版本。模型来源、revision、文件大小和校验值统一记录在
[`configs/vlm-models.json`](../configs/vlm-models.json)。

## 测试条件

使用同一 llama.cpp 二进制、同一 system prompt，语言 Q8_0 / 视觉 F16，CPU 核心 6、7，
推理/批处理均 2 线程，单槽 4096 token，关闭 context shift，prompt 缓存上限 128MiB。
未使用 GPU 或 NPU。测试 max_tokens=128、temperature=0.2、seed=42；网页日常上限为 256 token。

13 次文字问答覆盖中文闲聊、英文身份/偏好、上下文记忆、未知信息和一道算术题。
图片为同一张狗、自行车、汽车照片；保留各模型原生切图策略，因此视觉 token 数未必相同。
初始启动、文件缓存重启、驱逐权重页缓存后启动分别测首次图片和同图追问。
每次重启前等待温度降至 58°C 以下。256M 初始测试与下载末尾有少量重叠；其后两个启动条件无下载竞争。

TTFT 包含图像处理、视觉编码、prompt prefill 到首个输出 token 的耗时。
tok/s 是后端解码吞吐，不包括等待看图；同图追问命中已有上下文，不能代表新图片处理速度。
“驱逐权重缓存启动”用 `fincore` 确认权重驻留为零；不等于断电后整板冷启动。
此次未重复测整板上电，旧版 256M 系统重启记录见此前实测报告。

## 实测性能

下列范围是三个启动条件下的实际观测值，不是统计置信区间。

| 指标 | SmolVLM-256M | SmolVLM-500M | InternVL3-1B-Instruct |
| --- | ---: | ---: | ---: |
| 语言+视觉权重总大小（MiB） | 348.2 | 606.8 | 1235.1 |
| 已加载、短时空闲 RSS（MiB） | 586.5 | 1123.7 | 1707.2 |
| 推理峰值 RSS（MiB） | 703.8 | 1245.6 | 1980.8 |
| 推理峰值 cgroup 内存（MiB） | 867.8 | 1439.3 | 2541.3 |
| 纯文本解码（token/s） | 54.6–65.0 | 25.9–27.3 | 16.4–20.1 |
| 首次看图 TTFT（秒） | 20.29–24.07 | 22.43–23.95 | 199.39–218.66 |
| 首次看图完整回答（秒） | 21.49–25.06 | 24.25–25.85 | 202.12–221.50 |
| 看图后解码（token/s） | 34.4–41.2 | 16.0–16.4 | 7.8–8.1 |
| 同图颜色追问完整回答（秒） | 0.57–0.59 | 1.04–1.05 | 1.17–1.27 |
| 初始服务启动（秒） | 2.46 | 1.84 | 3.05 |
| 文件缓存保留的重启（秒） | 1.49 | 1.92 | 3.01 |
| 权重缓存清零后的启动（秒） | 6.66 | 11.42 | 22.81 |
| 首图进程 CPU 开销（CPU 秒） | 36.52–36.83 | 39.78–40.15 | 213.59–214.37 |
| 首图平均 CPU（单核=100%） | 145.7–171.4% | 153.9–165.4% | 96.8–105.7% |
| 推理阶段最高温度（°C） | 90.09 | 88.62 | 91.45 |
| 推理时整机最低可用内存（MiB） | 4900.0 | 4683.3 | 4194.5 |

5 秒短时空闲样本中三个模型 CPU 增量均为 0；不等于长期系统空闲功耗为零。
本轮整机 Swap 已用峰值分别约 0.5、0.5、1.25MiB，没有看到大规模交换。
A76 采样频率主要 2.002GHz，256M/1B 部分样本为 1.95GHz，500M/1B 的过渡样本含 416MHz；
未单独跟踪热节流事件，因此只报告观测值，不据此给出降频因果结论。

同一首图请求的 prompt token 数为 260 / 260 / 1342（含系统提示和文字），
这也解释了为什么三个模型不能按“相同 4096 窗口＝相同图片容量”理解。
当前日志未输出可单独分离的视觉编码耗时，原始结果该数组为空；没有编造视觉编码和 prefill 的拆分值。
网页等待后端的超时已从 180 秒调整至 360 秒，以覆盖本次 1B 首图实测；
更多图片或不同长宽比仍可能更慢、超时或耗尽上下文。

原始记录：[256M](benchmarks/2026-10-09-models/256m.json)、
[500M 与 1B](benchmarks/2026-10-09-models/candidates.json)。两次比较均正常完成，报告记录了线上服务恢复。
每个模型 3 次首图、3 次追问，另有初始中文看图与 13 次文字问答。

## 质量样例

| 问题 | 256M | 500M | 1B Instruct |
| --- | --- | --- | --- |
| 中文说“心情有点不好” | 无关的学习/食物回答 | 复述成英文“I'm not feeling well” | 连贯地回应情绪，并邀请倾诉 |
| 追问刚才吃了什么 | 未正确回忆黄焖鸡 | 回答黄焖鸡 | 回答黄焖鸡 |
| 记住宠物兔叫露娜 | 无关内容 | 把兔子说成驴/羊，名字错误 | 正确记住兔子名字 |
| 没提供兔子的颜色 | 无关内容 | 编造黄色 | 不编颜色，但拒答措辞过于宽泛 |
| 3+2−1 剩多少苹果 | 无关且混乱 | 正确回答 4 | 错误回答 5 |
| 英文问自行车颜色 | 红色，正确 | 红色，正确 | 红色，正确 |
| 中文描述图片及前后关系 | 不通顺/无关 | 不通顺/无关 | 中文连贯，识别黄色门廊/红色自行车，但未明确回答狗在车前还是后 |

逐图复核：图片确有黄色门廊、红色自行车及前方的狗，不能把“黄色门廊”算成幻觉。
1B 英文将外侧开口称为 window，中文对空间关系回答含糊；中文流畅不等于所有细节都正确。
网页使用 256 token 输出上限的独立验收中，1B 记住了露娜，但也自发推测兔子品种并给出冗长列表；
不要将“能记住名字”理解为消除了幻觉。网页未固定 seed，回答不必逐字重复评测脚本的结果。
网页实际首图完整回答 220.942 秒，动物颜色追问 2.327 秒；回答“黑白色”较粗略，未体现灰/米色毛发。
浏览器刷新后图片、两轮问答与模型标识都保留。
验收脚本通过代表请求/显示/存储正常，并不代表对模型答案给出了准确率认证。
记录见 [网页验收](benchmarks/2026-10-09-models/web-acceptance.json)、
[网页截图](benchmarks/2026-10-09-models/web-chat.png) 与 [原始测试图片](benchmarks/2026-10-09-models/test-image.jpg)。
以上是少量定性样例，不是准确率排行榜。原始答案、请求、采样和日志随报告保存，不只挑成功结果。

## 开销与限制

记录模型进程 RSS、systemd cgroup 内存、整机可用内存/Swap、CPU 秒数、100ms 温度与频率采样。
RSS 和 cgroup 口径不同：模型映射页和文件缓存可能由不同 cgroup 计费，不可直接互相替代。
CPU 百分比按单核 100% 计，两个核跑满约为 200%。板端没有可读的进程 I/O 计数时不虚构读写量。
没有电流计，未测瓦数、单次推理焦耳或电池续航。持续推理最高达 91.45°C，后续产品化需要改善散热。
不能只凭温度高或其他空闲核心的低频采样就宣称 A76 已降频。

## 复现与切换

板端文件：`/opt/opi-vlm/models/`、`/opt/opi-vlm/vlm-models.json`。
在板端以 root 运行，校验完成后同步切换模型服务和网页显示名；启动失败自动恢复原配置：

```bash
python3 /opt/opi-vlm/select_vlm_model.py smolvlm-256m
python3 /opt/opi-vlm/select_vlm_model.py smolvlm-500m
python3 /opt/opi-vlm/select_vlm_model.py internvl3-1b
```

每次选择其中一条。切换会中断正在生成的请求，不删除浏览器历史；建议新建对话比较各模型，
避免旧模型的错误回答继续进入新模型上下文。新回答会保存生成时的模型显示名。

```bash
python3 /opt/opi-vlm/compare_vlm_models.py \
  --models smolvlm-256m smolvlm-500m internvl3-1b \
  --output /opt/opi-vlm/new-comparison.json
```

比较脚本拒绝覆盖旧报告，暂时停止线上模型，结束后恢复；测试期间网页会显示模型未就绪。
[`scripts/compare_vlm_models.py`](../scripts/compare_vlm_models.py) 和
[`scripts/select_vlm_model.py`](../scripts/select_vlm_model.py) 与应用代码一起管理。
