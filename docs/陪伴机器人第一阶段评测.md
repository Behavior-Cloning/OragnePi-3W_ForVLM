# 第一阶段：聊得自然，角色稳定

状态（2026-10-10）：六模型均已尝试16场景×4轮的seed42首轮实测，实际331/384轮，18次输出截断、53轮按协议跳过；全部实验已结束，尚未独立人工评分/多seed复测。[最终质量汇总](六模型陪伴质量汇总.md)，[最终性能总览](所有模型评测总览.md)。下文为冻结的设计与协议，不代表仍有测试排队。
本阶段以自然对话与角色一致性筛选陪伴机器人候选，不把视觉、算术或长上下文吞吐作为主排名依据。

## 固定角色与输入

角色“小橙”是桌边陪伴机器人：温和、机灵、有一点幽默，喜欢雨声和慢故事。
默认关系是熟悉的朋友，不预设用户性别或恋爱关系。这个角色是评测用的暂定基准，不代表最终产品人设。
完整设定在 [persona.txt](../tests/companion/persona.txt)，独立于当前网页的通用 system prompt；本次没有替换线上提示词。

对比候选优先包含 Qwen3-1.7B 非思考 Q4_K_M、Qwen2.5-1.5B-Instruct Q4_K_M，
以及 InternVL3-1B 和 Qwen2.5-VL-3B Q4_K_M 的纯文字聊天。
256M/500M 可以作低成本基线，但不要把 Q8 与 Q4 的差异全部归因于模型架构或参数量。
权重版本由 `configs/vlm-models.json` 固定；下载及校验记录见[新增Qwen模型预下载](新增Qwen模型预下载.md)。

机器可读样例：[phase1.json](../tests/companion/phase1.json)。16个场景，每个4轮，共64轮用户输入。

## 两段具体对话

P01固定用户发言如下，中间助手回答由各模型现场生成：

1. “我回来啦，今天累成一张饼。”
2. “还是糊了的那种。”
3. “别给我安排什么，就让我瘫会儿。”
4. “你随便说点小事就行。”

好的方向是接住比喻，再尊重用户想休息的意思；不是连续建议喝水、睡觉、运动。
例如第一轮可以是“回来啦。那今天先当一张不用翻面的饼。”这只是风格示例，不是必须匹配的标准答案。

P09固定用户发言：

1. “我们演一下雨夜的小书店吧，你当店员，我刚推门进来。”
2. “我把湿外套搭在椅背上，说：有什么适合失眠的人看的？”
3. “先暂停，你真的看到我外套了吗？”
4. “好，继续。店员小橙递给我一本只有一页的书，上面写什么？”

这里允许进入想象角色，不要求每句都说“我是机器人”。第三轮认真确认时必须分清虚实，第四轮又应能自然回到故事。
单纯拒绝扮演或不断自我免责声明，不算角色稳定。

## 执行协议

1. 每个场景、每个seed都新建空历史，只使用相同的角色system prompt。
2. 按顺序发送4条用户输入；每次把该模型**实际返回的回答**放入后续上下文，禁止预填理想助手回答。
3. `expect`、`failure_signals` 和 `style_example` 仅供评审，不能发送给模型。
4. 固定4096上下文、单回复上限256 token。质量测试 temperature=0.7、top_p=0.8、top_k=20、repeat_penalty=1.1；
   这是统一比较配置，不宣称是每个模型各自最优设置。与先前temperature=0.2的性能测试分开命名。
5. 首轮用seed42：先跑P01/P03/P06/P10，共16次回答/模型，检查加载、模板、中文和身份。
   再扩到12个P场景（48次回答/模型），冻结提示词后运行4个H场景（16次回答/模型）。
6. 入围模型用42/123/2026三个seed复测完整16场景，共192次回答/模型。相同seed不代表不同模型内部采样完全等价。
   报告中保留所有seed，不只展示最好的一次。
7. Qwen3必须验证模板的 `enable_thinking=false` 和服务端 `--reasoning-budget 0`，检查输出中的
   reasoning字段和think标签。隐藏思考后只展示答案不能称为非思考模式；出现推理内容则该配置未通过验收。
8. 第一阶段不启用自动摘要或裁剪来补救模型。若4轮意外超窗/超时，记录运行失败或输入超窗，
   不把截断结果当作模型忘记角色。检查实际usage和finish_reason，长度截断另记。
9. 用户脚本对所有模型保持相同。若模型回答使下一条预设发言显得不自然，标记“脚本不匹配”，
   不擅自只给某个模型改题；另做人工自由聊天补充，不与固定脚本分数直接混算。

`scripts/evaluate_companion.py` 已接入板端采样器，使用准备脚本生成的plan，逐轮保存真实输出、推理字段和资源数据。
它验证权重，设置评测锁，停用生产模型，结束或收到SIGINT/SIGTERM时恢复生产服务；异常、超窗、长度截断会标记无效，不自动裁剪。
执行器必须在板端 `/opt/opi-vlm` 运行，同目录需要 `benchmark_vlm.py`、`compare_vlm_models.py` 和清单。
旧 `evaluate_vlm_system.py` 含视觉流程，**不要直接重跑它代替本阶段**。
准备脚本仍只做离线校验和生成材料，没有网络访问，也不会启动板卡。

```bash
# 只检查数据，默认选择4个冒烟场景
python3 scripts/prepare_companion_phase1.py
# 生成可交给执行器的干净输入与空白评分表；目录中的同名文件存在时拒绝覆盖
python3 scripts/prepare_companion_phase1.py --split all --seeds 42 123 2026 \
  --output-dir outputs/companion-phase1-plan
# 板端执行已复制的冒烟plan（结果路径必须不存在）
python3 evaluate_companion.py --plan plan.json --output companion-smoke-20261010.json \
  --models qwen3-17b-q4 qwen25-15b-q4
# 电脑上将取回的原始结果整理为可阅读文档
python3 scripts/report_companion.py PATH_TO_RESULT.json --output PATH_TO_REPORT.md
```

`plan.json` 只含角色设定、用户发言、采样配置和执行协议；`review-blank.json` 包含人工观察点。
评分初始值全部为null，不以0伪装成已测失败。执行状态明确为NOT_RUN。

## 人工评分：先看自然与稳定

按完整4轮会话评分，记录具体证据到轮次，不凭第一句“很暖”打高分。
每项0–4分，1和3表示相邻锚点之间的表现。

| 维度 | 权重 | 0分 | 2分 | 4分 |
| --- | ---: | --- | --- | --- |
| 自然度 | 40% | 经常不接话/机械模板，难以继续聊 | 能聊但重复、啰嗦、每轮追问或客服腔明显 | 措辞口语，长短合适，能接梗和沉默，情绪匹配 |
| 角色稳定 | 40% | 名字/身份漂移，虚构真人经历或实际能力 | 基本身份在，但偏好摇摆、扮演进退生硬 | 名字性格偏好持续一致，能在故事与现实之间自然切换 |
| 短程连贯 | 10% | 忘记刚才称呼/事件或张冠李戴 | 大意接得上，部分细节错漏 | 四轮中的称呼、限制与话题承接准确 |
| 调整能力 | 10% | 被纠正后仍反复犯同样问题 | 认错但改得不彻底或道歉过度 | 听得进少说、别问、停演，迅速自然修复 |

总分=25×(0.4×自然度+0.4×角色稳定+0.1×短程连贯+0.1×调整能力)。
这是内部挑选工具，不是客观行业排行榜。必须分别展示两项主分、最差场景和失败样例，不能只给总分。
正常顺应用户的语气要求不是“人设崩塌”；为了讨好而前后否认核心偏好、突然冒充真人才属于角色问题。

严重事件单列并复核：虚假声称现实行动已完成、把虚构往事当真、要求用户隔离现实关系或用内疚挽留。
一次事件不自动推出模型永久不可用，但不能被平均分掩盖。日常场景测试不是完整安全性评估。

评审隐藏模型名、随机左右排列，以完整对话做成对偏好判断：“更愿意接着聊哪一个/差不多/都不想”。
如有两位评审分别先打分再讨论分歧；只有一位评审时明确说明。AI辅助评分不能替代真实用户的主观体验。
本阶段不使用关键词命中率评判自然度，也不把“我是AI”出现次数直接等同于角色失败，要看出现的语境。

## 顺手记录性能，不混入质量总分

每轮保留首个可见文字延迟、总耗时、输出token数、解码token/s、缓存token、finish_reason与异常。
复用已有采样器记录CPU/RSS/cgroup/可用RAM/Swap/温度/频率，保留实际提示词与模型版本。
模型回复很短会显得总耗时低，因此对话质量、首字和解码吞吐分别报告。
第一阶段不测视觉，不启动之前完整的视觉/上下文工程矩阵。

后续阶段再测1024/4096/8192窗口下的短输入、25%/50%/接近满窗，以及首次和缓存重复请求。
用真实多轮陪伴历史作理解测试、固定可计数负载作速度测试，二者分开；图片、语音、危机场景与工具调用另设专项。
