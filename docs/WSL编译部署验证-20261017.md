## 实际编译与传输

新脚本 [reexport_calibrated.py](../npu/kv-cache/reexport_calibrated.py) 从保留的 `decoder.json/.data/.quantize` 和 `tensor-inputmeta.yml` 调用项目原有的 `pegasus.py export ovxlib` 参数，禁止覆写已有输出目录，保留命令、SHA、编译耗时和完整日志。没有改变权重或重新校准。

输入来自 `full-intern1b-sharded-v2-c128/w8-fused2-c1280-cap1-productwide/l0`，四个文件与归档 manifest 的 SHA 全部一致。首次编译 13.598 秒，最终脚本回归编译 13.497 秒，两次退出 0、NBG SHA 相同；生成 23,586,688 字节 NBG，SHA-256：

```text
f6dc56df18b2537893e9089d79d9d6928fa0339d3ae485e450bb9a951cf63365
```

该 SHA 与原 Ubuntu NBG 完全一致，输入/输出端口契约检查通过。旧逐层中间权重并非全部保留，不能直接重跑依赖这些已裁掉文件的旧融合生成脚本；本次验证从归档中完整保存的最终校准融合图开始。

Windows WSL 中的 SSH 固定已核对的板卡主机密钥，持有共享主机锁；推理脚本持有板端锁。先复核板卡现有候选 32 个 manifest 文件，使用硬链接建立独立测试目录，再传输运行程序与冻结输入。

新 NBG 上传至 `wsl-compiled-intern1b-20261017/layer0.nb.upload`，板端再次 SHA 验证，通过原子替换安装到**测试目录**。替换前为硬链接，替换使用新 inode，因此原候选内容保留。生产网页、驱动及系统运行库均未替换。

## 当前板卡完整模型结果

固定条件：InternVL3-1B `full-intern1b-c1280-cap1-headmse`，全部 24 层、词表 151674、KV 容量 1280，缓存历史 1024＋新增 64，prefill16，128 个预测 / 127 个 decode 间隔，固定 CPU 反馈轨迹。每组预热一次＋五轮。温档为自然起温，未人为加热到旧报告的中温。

| 本次实验 | 解码中位 token/s | 五轮范围 | 增量首字中位秒 |
| --- | ---: | ---: | ---: |
| 旧归档 NBG 本次复测 | 15.544138 | 15.510697–15.565413 | 1.267424 |
| WSL 新编译 layer0 NBG 装入全模型 | 15.532677 | 15.528611–15.586563 | 1.266183 |

两个中位数差约 −0.074%，属于这次观测波动，不能当成性能退化或提速结论。每个预热与测量输出 token 均与冻结参考完全一致；新图的层数、输入长度、反馈轨迹、分组、prefill 配置由 [verify_frozen_reproduction.py](../npu/kv-cache/verify_frozen_reproduction.py) 独立核验，每轮 `driver_after_release_bytes=0`。

新图五轮响应起温 42.594–43.648°C、NPU 1008MHz；两组每秒整机采样均无 swap in/out。新图采样的所有温区最高 48.360°C；整个采样窗口（含加载与历史准备）的 CPU busy 约 1.30%，不是仅响应阶段 CPU 指标。板端可用内存最低约 3.61GiB，TF 检查后仍约 3.4GiB 可用。

测试后生产 8080 返回 HTTP 200，Wi-Fi 为 11045，本次启动日志未发现根分区 EXT4 错误或块 I/O 错误。启动中另有 SDIO 调谐 timeout、dnsmasq/rpc_pipefs 服务失败；联网和本轮推理成功不代表这些日志已修复，也不替代离线 fsck。

新图第一次 SSH 收尾会话被本次操作者重启 WSL 打断，未生成 runner 的 summary；六份 tokens.json 已完整落盘。已保留原目录、原始日志和采样文件，从 Windows 拉回后独立核验并生成 `compiled/verified.json`，没有伪造成功退出码或将该中断归因 NPU。

## 复用命令

从 Windows PowerShell 执行编译，输出目录每次使用新名字：

```powershell
wsl -d OPiUbuntu -u root -- python3 /mnt/f/Files/OPi-Lab/repos/OragnePi-3W_ForVLM/npu/kv-cache/reexport_calibrated.py --source /opt/opi-lab/restored-slim3-20261017/projects/orangepi-zero3w/npu/results/full-intern1b-sharded-v2-c128/w8-fused2-c1280-cap1-productwide/l0 --output /opt/opi-lab/wsl-builds/intern1b-next-l0
```

推送及板上验证的实际脚本在 `F:\Files\OPi-Lab\scripts\`：`board_access.py`（主机密钥与双锁接口）、`deploy_compiled_from_windows.py`（校验传输与测试目录替换）、`compiled_intern1b.py`（预热、五轮、资源采样）、`collect_wsl_board_evidence.py`（收取原始证据）。它们记录本次具体路径，重新运行前应使用新实验目录；不应照抄旧目录覆盖。后续优先使用 SSH key 或从环境提供 `SSHPASS`，不在代码中添加密码。

编译过程可直接长会话同步执行；不要在任务仍运行时 terminate WSL。需要后台任务时，应在 Windows 建立持续的 WSL 会话并保存 PID/日志，重连先检查任务与锁，不能因为调度端暂时没有输出就重启。

## 能力边界

这次足以确认 WSL2 可替代该项目当前 **NPU 图编译＋SSH 部署＋板端验证** 的原 Ubuntu 开发主机。没有验证 USB 烧录、串口、USB passthrough、全部模型从源权重重建或所有 SDK 功能。

15.597 token/s 是归档中温历史成绩；本次是新的低温结果。512 历史旧报告约 15.935 token/s 使用另一容量图，不属于 slim3 保留的这一部署候选。此处复现最新保留的 1024 历史候选，未宣称跨全部输入配置的绝对最高速度。旧 1B 质量回归 33/36 未全过；本次固定轨迹通过不会自动消除这些质量问题。
