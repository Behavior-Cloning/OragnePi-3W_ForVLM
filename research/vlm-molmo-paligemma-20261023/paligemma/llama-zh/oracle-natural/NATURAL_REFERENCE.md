# FuseChat 中文 Q4 / Q8：WSL FP32 自然输出参考

2026-10-23。两种源权重均完成同一组 3 个中文输入的完整 16 层参考生成；greedy、最多 96 个新 token、保留完整 128256 维 logits。这里是将 GGUF 权重反量化为 FP32 后执行的数学参考，既不是原始 BF16 基准，也不是板卡性能测试。

结论：Q4 与 Q8 都能生成连贯中文，但都存在冗长、措辞不自然、将直接请求变成泛泛建议的问题。不能将这些源参考中已经出现的现象归因于 NPU；也不能凭这 3 例断言 Q8 的整体中文准确率更高。Q8 在“陪我聊两句”一例输出较简短，另外两例也未充分遵循 system 的“简短”要求。

## 可比条件与证据

- 同一 FuseChat 微调模型、同一 bartowski ModelScope 镜像 revision；Q4/Q8 的全部 tokenizer metadata、张量名称/形状和 llama.* 参数一致。
- 从同源 FuseAI 镜像取得原始 tokenizer.json，SHA `bbc1904d35169c542dffbe1f7589a5994ec7426d9e5b609d07bab876f32e97ab`。9 组中文/数字日期/英文换行/prefix/完整 prompt 与 GGUF 重建 tokenizer 的 token IDs 全部一致。
- 输入长度分别为 38、41、42 tokens。最大上下文 256，EOS 配置保持原模型的 128001/128008/128009。
- Q4 三例的前 32 步与原诊断参考逐 token 完全一致；原 `reference-q4.json`、ROOT inputs、assets 和校准文件未修改。
- 数值代码来自 full-NPU 工作目录的 model/trained_probe/probe/generate_reference 快照；只改变数据来源、输出目录和结果元数据，不改层计算。源代码 SHA、有限修改说明见 `source-provenance.json`。

## 数值解读

三例首个生成 token 都发生 Q4/Q8 分歧，这是相同输入条件下的真实量化源差异；它不等于三例都错误。首步 top-10 候选集合重叠分别 9/10、8/10、8/10。去除共同偏置后的首步 logits RMSE 约 0.413、0.501、0.410，KL(Q8‖Q4) 分别 0.073、0.301、0.220 nats。生成一旦分叉，后续条件上下文已不同，因此没有把随后 logits 的逐位置差异当成量化误差。

后续 NPU 输出应与**相同源量化**的参考比较：Q4-source NPU 对 Q4 参考，Q8-source NPU 对 Q8 参考。Q8 参考仍不是 BF16 真值。
