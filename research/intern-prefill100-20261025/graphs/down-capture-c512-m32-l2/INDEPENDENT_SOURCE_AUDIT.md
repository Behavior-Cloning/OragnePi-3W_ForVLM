# Down capture 源码独立审计

通过独立诊断源码审计，未操作板卡/SDK。原图只增加两条 output；原节点、量化、输入元数据、权重数据与实际导出 payload 相同。生成 C 的33个常量块和原16个端口张量定义相同；顺序为原5输出再接两个 down，每个32×4864，生成 C/nbg_meta 标为FP16。

私有 runtime 只扩大 Layer.out 容量到7，允许实际5或7输出，并为新增输出断言C512/M32和155648元素。输出初始化、flush、读取、重复一致性、resident copy和释放均按实际 no 循环，5口基线不会访问未初始化的6/7口。复原这三处改动后与旧compact probe源逐字相同；原生产文件未改。

新增输出总F32归档1425408字节，原5口180224字节。结构上未见越界；错误路径会退出进程，仍需外层确认driver释放。API计时只包vip_run_network，显式flush/invalidate在外。

这不是观测无扰动证明：需原/诊断/原同输入原5输出逐字节门禁。FP16仅为生成C/metadata静态证据，本审计没有实际SDK二进制导入。此canonical输入来自FP32历史，不是真实全NPU前缀或system pos0，不能外推完整模型质量/时延。
