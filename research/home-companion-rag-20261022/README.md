# 家庭／桌面陪伴动作召回复测（2026-10-22）

用户要求：原子动作、高层指令和组合技能均限定日常家庭陪伴；查询文档、历史、修改超时等管理接口不得混入动作字典。只有在该高层指令下明确不能执行或冲突的候选才算不相关。

## 冻结资产

- `atoms.json`：35 个原子动作，头部、表情、手势、上身小幅姿态及静止；没有管理、声源估计、检测等内部 API，也没有底盘位移、跳跃或抓握。
- `skills.json`：20 个家庭陪伴组合技能，步骤只引用上述原子动作。与原子词典分榜；不混排后重复执行。
- `cases.json`：30 个家庭／桌面场景各两种说法，共60条；涵盖迎接、陪读、倾诉、安慰、庆祝、晚安、早晨舒展、休息、音乐、感谢、道歉、告别、观察桌面物品等。
- `fixture-manifest.json`：冻结数据 SHA-256。所有样例是助手生成并复核，非真人独立盲测；两个同场景说法不能当作独立场景。
- `removed-from-old.json`：旧256库未直接沿用项清单。历史结果保留，不静默覆盖。
- `guard-cases.json`：执行层停止／能力不足场景的规格样例，不加入召回准确率。它们未构成已部署的执行器安全验证。

## 执行语义与评审

Top-K 是候选动作集，不是概率或完整计划。评审分 compatible / conditional / incompatible；非最佳或不在目标标签表中不自动成为负例。条件缺失、风格不明和先后关系未定列为 conditional。目标定位由外部提供；硬件能力、运动限位和传感器成本未在本轮测量。所有动作是 mock 描述，板上只做检索推理。

默认候选需要串行安排，共用执行器不能直接并行。保留每个原子候选，不通过删除难项来改善Top-K指标；组合技能展开后另外检查重复步骤和明确的阶段顺序。没有实机动作时序、关节极限或真实任务完成率结论。

主审与独立审计先阅读完整60×55矩阵，再查看模型排名。以同一套裁决评估全部模型。前K全兼容、含条件但无硬冲突、至少一个硬冲突分别报告，同时报告实际返回数，返回不足K不冒充K项全正确。主目标线索命中单独列出，它不是用户定义的可执行性。

## 复现

权重复用 F:/Files/OPi-Lab/experiments/board-rag-atoms-20261021/larger256-20261022-v1/models，BGE-small复用此前板端常驻目录。代码在 Windows F盘仓库，WSL控制板卡。controller.py 经 board_access.hostlock 和板端 flock 串行调度各模型；输出哈希核验完成才删除本轮板端暂存权重，F盘源权重保留。

运行 `python3 -u controller.py`；每个模型热身后，60条输入×原子/技能两种独立请求×2次，共240次计时。每次重新编码query，预编码候选不计入热态查询延迟。A76 CPU6/7、2线程、FP32；温控与内存阈值沿用已验证基准。

结果在 `results/<model>/`，完成语义裁决后运行 `python3 analyze.py`，最终报告为 `HOME_COMPANION_RAG_REPORT.md`。

实测源码保存在source-versions/board_bench-measured-v1.py，当前入口仅清理了本轮语料不包含的控制请求分支。具体差异与哈希见报告。
