# C448 原量化主图＋真实8-token尾图：完整24层对齐测试 r4

2026-10-26。运行ID `c448-matrix-r4`；控制器与板端均 returncode=0。

本轮保留原始 L2/L3 量化，仅比较同一个 C448 runtime 的 M32 补齐尾段与 M8 真尾段。A→B→A 顺序为 original、tail8、original-repeat。不是此前 range16 或 row-scale 量化候选。没有修改生产默认。

结论：8格中的 TTFT P50 从原组1.04–3.20秒降至 tail8 的0.81–2.96秒，约降低6.5%–22.2%；decode未见确定提高。100ms全范围目标仍未达到。6份四步完整logits复核有限值、长度、实际SHA并按输入跨组逐字节相同；12个自然输出和24个固定反馈输出跨组三组均相同。这只证明当前样本的一致性，不能等同中文正确率或动作安全通过。

## 实验口径

- system64 = 正文59 + 模板5；system128 = 正文123 + 模板5。
- 动态正文64/128/192/256，额外模板8，实际新增prefill72/136/200/264。每次重置后只准备并复用system KV，没有动态缓存复用。
- TTFT从LLM动态请求开始计；system冷构建、ASR/VAD等待不计入。速度请求输出32 token，用固定反馈100662；decode = 31 / (total−TTFT)，不是自然回复吞吐。
- 每格3个冻结成本输入，使用标点补齐；P50为这3个样本中位数，P95采用nearest-rank，n=3时等于最大值，不能称长期稳定达标。
- Intern文本NPU 24层；降噪、KWS、VAD、流式ASR处理合成录音；RAG仅常驻，本轮不执行检索。不含视觉、真实麦克风、执行电机。
- 主图M32，tail8在B组每次实际调用1次，scalar_prompt_tokens=0；其余图、量化、token IDs、亲和4/5、输出协议相同。
