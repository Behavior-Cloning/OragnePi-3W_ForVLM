# MiniCPM-V 4.6：A733 NPU INT8 实测与优化

更新：2026-10-23。**INT8 权重已在 NPU 跑通，但还没有达到替代 Intern 1B 的速度与精度要求。** 较保守路径 3.77 tokens/s，仅加速普通注意力 4.14 tokens/s。最快候选 5.92 tokens/s，但晚安测试出现明显重复，不能推荐。同板新测 Intern 为 15.5–15.7 tokens/s。

24 个语言层和完整词表输出均在 NPU，CPU 负责 embedding 查表、缓存复制、RoPE 参数准备和 argmax。**图像编码器尚未部署，这不是完整图文 VLM 或语音链路测试。** 早期证据见 REPORT_FP16_INITIAL.md。

## 速度与比较口径

一次加载后运行 3 轮，每轮清空状态；表格取后两轮中位数。MiniCPM 输入 31 token、固定输出 16 token、batch=1、容量 128、逐 token 预填充、无前缀复用。decode 计算首 token 后的 15 个 token；TTFT 排除加载。

| 路径 | TTFT，秒 | decode，tokens/s | 驱动分配，MiB |
|---|---:|---:|---:|
| 原始 FP16 修正版 | 17.553 | 1.306 | 1491.9 |
| W8、家庭语料校准 | 7.505 | 3.531 | 709.3 |
| 稳定归一化＋分组执行 | 7.031 | 3.766 | 709.0 |
| 仅普通注意力 MatMul 加速 | 6.275 | 4.136 | 708.2 |
| 仅线性状态 MatMul 加速 | 4.784 | 5.176 | 727.1 |
| 两者同时加速 | 4.035 | 5.917 | 726.6 |
| Intern：31 token 对照 | 1.261 | 15.715 | 718.4 |
| Intern：相同中文消息 | 1.010 | 15.523 | 718.4 |

31-token Intern 输入是原有模板 token 的末尾 31 个，仅为计算形状对照，不能说语义相同。随后补测相同 system“你是家庭陪伴机器人，简短回答。”和用户“你好，请介绍一下自己。”：MiniCPM 31 token，Intern 27 token；均输出 16 token，reset、零前缀复用。

Intern 使用已有优化路径：容量 1280、16-token 批预填充、分组执行。MiniCPM 仍逐 token 预填充，TTFT 差距包含实现差异。decode 排除了预填充时间，但容量、结构、量化路径仍不同。两者均绑定 CPU6/7、顺序使用同一 NPU，已有 CPU 服务保持原样。两轮常驻样本不能支撑可靠 P95、长期稳定性或速度上限。所有完整模型测试退出后驱动分配回到 0。

## 短上下文为什么未体现线性注意力优势

这个判断合理，但不能把全部差距归因于架构。

- 普通注意力 decode 已有 KV cache，每步注意力工作量约 O(Ld)；线性注意力更新固定矩阵状态，约 O(d_k d_v)。后者随历史长度增长更有利，却有固定成本。不能用完整序列 O(L²) 推断短上下文单 token 解码一定更慢。[Gated DeltaNet 原论文](https://arxiv.org/abs/2412.06464)
- 本模型 18 个线性层，每层状态为 16×128×128＝262,144 个元素，FP16 状态合计约 9 MiB，另有卷积状态。几十个 token 时，固定更新成本可能超过省下的 KV 扫描；尚未实测性能交叉点。
- 两者语言层都是 24 层。MiniCPM 总参数 1,300,428,016；语言 752,161,600，视觉含内部 merger 522,299,312，外部 merger 25,967,104。本权重并非“0.9B＋0.4B”，层数也没有低于当前 Intern。
- MiniCPM 词表 248,094、hidden 1024；Intern 为 151,674、896。输出矩阵约 2.54 亿对 1.36 亿元素，线性注意力不会消除这部分计算。Intern GGUF 有独立 embedding/output 张量，总计 629,697,920 元素，不能未经验证当成共享权重。
- A733 算子映射也有实际影响：普通注意力单层换用 INT16 MatMul 输入后 8.85→4.65 ms；线性层可到 4–5 ms，却放大误差。当前结果不是硬件或模型的理论速度上限。

MiniCPM 还有 6 个普通注意力层，因此整个模型并非恒定历史成本。当前 NPU 图按固定容量执行；单纯改变有效 prompt 长度不能代替控制编译容量的复杂度对照。长上下文优势仍需单独验证。

## INT8 跑通与优化记录

采用 FC 权重 INT8＋校准后的 INT16 定点边界＋敏感算子 FP16，**不是全模型 W8A8**。生成 C 中核对了 194 个 FC 权重确为 INT8；卷积、归一化、状态、embedding 等仍有浮点。

原先直接换 W8 失败。参考 Intern 路径后，在每个 FC 前显式插入 dtype_converter，修复只改变 reshape 元数据而没有实际转换的问题，24 层及 8 个词表分片才全部编译并运行成功。

校准来自官方 FP32 参考的 8 条家庭对话及每条 4 个生成状态，FC 每模块记录 299 行；逐头状态范围另外遍历所有 token。校准语料不是独立精度集。普通注意力 MatMul 范围目前仅来自单个真实状态并留 2 bit 裕量，覆盖不足仍需解决。

| 尝试 | 实测结果 | 处理 |
|---|---|---|
| W8、显式转换、家庭语料校准 | 1.31→3.53 tokens/s | 跑通 |
| 线性核心等价放大 32 倍、保持 RMS epsilon 等价 | l0 隐状态相对 L2 约 21.27%→3.34% | 保留；FP32 等价检查最大差 2.42e-8 |
| VIP 分组执行、hidden buffer 复用 | 3.54→3.77 tokens/s，token 不变 | 保留 |
| 普通注意力 INT16 MatMul 输入、FP16 输出 | l3 8.85→4.65 ms，误差 1.394%→1.383%；全模型 4.14 tokens/s | 实验候选，尚未验收精度 |
| 线性 MatMul 定点输入 | l0 9.20→4.04 ms，误差约 10.14% | 不直接采用 |
| 逐头动态归一化 | l0 8.49 ms，误差 3.34% | 动态最大值/除法抵消收益 |
| 固定逐头缩放 | l0 5.27 ms，误差 4.15%；组合全模型 5.92 tokens/s | 出现重复，拒绝推荐 |
| W8A8 | l0/l3 误差约 40%/60%，基本不提速 | 拒绝 |
| DFP INT8 权重搜索 | 小幅提速、误差增加 | 未选用 |
| 原生 RMSNorm | 没有解决精度问题 | 未选用 |
| FP16 逐元素替代 MatMul | l0 7.30 ms，误差 6.07% | 全层已编译，但未测完整模型，不报整体速度 |

NPD 返回数据缺少 3 个批量 MatMul 节点；“FC 占已记录周期约 80%”不能等同整层墙钟占比。瓶颈判断主要依据配对替换实验。

## 精度证据与失败案例

每一步把 NPU 实际选中的 token 历史喂给官方 FP32，再比较下一 token，避免自由生成上下文分叉造成误判。**这是数值一致性，不是任务准确率。**

| 路径 | 校准问候语同历史一致数 | 4 条未参与校准的家庭输入 |
|---|---:|---|
| W8、未修复归一化 | 11/16 | 未完成本组对照 |
| 稳定归一化＋分组 | 16/16 | 安慰、加法、原地问好、晚安可读，但与 FP32 有差异 |
| 仅普通注意力加速 | 12/16 | 四条解码文本与上一行相同，问候语有变化 |
| 仅线性状态加速 | 5/16 | 晚安出现“请请请请……” |
| 两者同时加速 | 9/16 | 晚安也明显重复 |

较保守路径四例的一致数为 4/16、6/7、4/6、10/15。数学题 NPU 回答“二加三等于五”，FP32 回答“五”；不同不等于答错。相反，晚安重复是明确退化。不能用 5.92 tokens/s 代表可部署性能，也不能因一条问候语 16/16 就宣称整模型精度达标。

## 资源和存储

较保守分组版驱动分配约 709 MiB，推理进程占 0.076 个 CPU 核；最快但有质量问题的版本约 727 MiB、0.119 个核。进程 RSS 约 6 MiB，不能代替驱动内存，也不包含完整视觉模型。

最快候选约 21 秒三轮测试和约 29 秒四例检查，以 0.5 秒采样：全系统 CPU 平均约 3.21% 和 2.90%（8 核总容量，扣除 iowait）；最小 MemAvailable 约 3.71 GiB。连续温度采样最高 42.72°C，轮次边界还记录到 43.34°C。测试前已有 swap；测量期间分别增加约 26.5 MiB、3.25 MiB，不能宣称无 swap。未做长期压力测试。

读取到 NPU performance 模式 1008 MHz，A76 2002 MHz，未修改 governor。短测没有显示高温降频是主要原因，但没有连续 NPU 时钟曲线。

本轮额外清理，不与上轮重复相加：

- WSL：按硬链接去重释放 **14.24 GiB** 可再生 ONNX、decoder.data、编译目标。
- 板卡：释放 **2.32 GiB**，可用约 **4.86 GiB**。旧 FP16 NBG 先核对 WSL 副本哈希，再删除板上副本；单层探针及旧 W8 也已清理。
- F 盘最终物理可用约 23.34 GiB；WSL 内部释放不等于 VHDX 立即缩小。未关闭共享 WSL 做离线压缩。
